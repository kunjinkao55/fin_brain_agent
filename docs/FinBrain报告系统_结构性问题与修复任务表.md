
# FinBrain 报告系统：结构性问题诊断与待修复任务表

> 依据：托伦斯（301583）报告人工核验（2026-07-26，对照 iFinD 行情/财报/财务指标及《上市公告书》《招股说明书》）。
> 本次人工核验共发现 **18 项问题**，系统自动审计仅检出 **1 项**（SELL 与买入价矛盾），**自动检出率 ≈6%**。
> 结论：错误非孤立数字失误，而是数据源、数据处理、生成校验三层的结构性缺陷，**会在其他个股上系统性复现**。

---

## 一、三层结构性根因

```
┌─ L1 数据源层（Data Source）
│   次新股关键数据集缺失（IPO发行参数/业绩预告/解禁日程/流通盘）
│   股本变动无统一事件流；单一免费源、无交叉验证
│
├─ L2 数据处理层（Data Processing / 口径）
│   股本无单一事实源(SSOT)；分子分母时点错配；事件误分类；
│   交易规则缺失；指标禁用状态不广播；单位/舍入不统一
│
└─ L3 生成与校验层（Generation & QA）
    LLM 定量结论无计算验证；跨模块一致性守卫缺失；
    审计警告不闭环；审计覆盖率不足（假阴性"0问题"）
```

**根因传播链示例（托伦斯案例）**：事件误分类（IPO→定增，L2）→ 错误股本/错误摊薄系数（L2）→ 错误 BPS → PB 错 → 止损价错（L2→L3）→ 全部通过审计发布（L3 失守）。**修复必须自下而上：先数据地基，再口径守卫，最后校验闭环。**
